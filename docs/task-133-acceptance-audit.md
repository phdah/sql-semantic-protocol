## Finite source and terminal evidence

The [task-owned v3 freeze](task-133-acceptance-freeze.json) registers both `76-C133-P` and `76-C133-N` families. It contains **9 mandatory Exact** cases: portable LIMIT/OFFSET, FETCH FIRST, semantically equivalent TOP (MSSQL parser only for native syntax, with DuckDB LIMIT oracle), descending total order, projection alias, explicit NULLS LAST, LIMIT zero, empty source and offset-past-end. **4 conditional Residual** cases: duplicate/tied ORDER BY, implicit NULL ordering, missing total ORDER BY and unresolved CTE producer. The CTE producer residual remains owned for future TASK-135 composition and is not claimed as implemented here.

Every case includes exact SQL, stable source relation/column and `s#N` row identities, complete physical source bag, sorted terminal bag or explicitly unproved terminal, positive and NOT TRUE source membership, output scalar type, nullable finite domains, inclusive numeric extrema where values exist, conditional owner/disposition and native execution boundary. Exact duplicate physical identities are never collapsed. Full-bag absence requested by the public API is **Impossible** (not an invented empty source); input-schema contradiction is independently Impossible. Ties across physical keys cannot produce stable identity and remain typed Residual.

- **117/117 mandatory parser/canonical Exact cells** across all 13 exposed dialects, plus **52/52 conditional parser/canonical Residual cells**. Total: **169/169**. The actual complete terminal bag, stable physical source IDs, selected and rejected partitions, and exact output domains are compared across equivalent canonical adapters. Both enabled and disabled `odcs` feature configurations are checked.
- `tests/task_133_frozen_matrix.rs` executes independent DuckDB complete physical input and ordered terminal snapshots for every mandatory case (8 native direct SELECT variants plus one TOP-to-LIMIT equivalent), asserts all frozen source identities, exact NULL and finite domains, plus positive/negative requested-row membership for each. `tests/task_133_page_bags.rs` separately proves a source INTEGER overflow Impossible, NULL/duplicate/underordering Residual and an uncomposed WHERE/CTE/derived/DISTINCT producer boundary.
- The committed `task133_source.csv` seed and `task133_pagination.sql` model are run by real dbt Core twice (plus docs/catalog generation). `tests/task_133_dbt_core_e2e.rs` checks the executed DuckDB source and materialized output against the analyzed compiled manifest/catalog and canonical physical-bag proof. The existing dbt golden is preserved by excluding the separately verified TASK-133 model from the legacy fixed model snapshot. The active query JSON schema and canonical emitted `row_shaping` have separate golden assertions.

Non-DuckDB runtime, T-SQL native TOP, implicit NULL ordering in vendor/session settings, WITH TIES and stochastic TABLESAMPLE are **not** certified here. The first two are explicitly owned conditional boundaries; WITH TIES belongs to TASK-134 and sampling to TASK-136. Those are not missing mandatory TASK-133 exact cases and cannot be silently upgraded to Exact.
